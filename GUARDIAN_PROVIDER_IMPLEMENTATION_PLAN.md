# Guardian to Provider Migration - Implementation Plan

**Date**: November 6, 2025  
**Status**: Ready for Implementation  
**Priority**: Medium (Performance + Code Quality Improvement)  
**Estimated Time**: 3-4 days  

---

## 📋 Executive Summary

### Objective

Consolidate guardian and provider systems into a single provider-based architecture, reducing code complexity by ~30% and improving maintainability.

### Current Status

- ✅ **Phase 1 Complete**: Schema changes deployed
- ✅ **Migration File Created**: guardianToProviderMigration.ts (TypeScript errors fixed)
- ⏳ **Pending**: Convex deployment (service was experiencing 503 errors)
- ⏳ **Next**: Backend updates, frontend updates, E2E tests

### Key Benefits

1. **Code Reduction**: ~1,200 lines of duplicate logic removed
2. **Simplified Data Model**: One entity type instead of two
3. **Better UX**: Consistent provider selection across all features
4. **Easier Maintenance**: Single code path for non-school entities
5. **Flexibility**: Easy to add new provider categories

---

## 🎯 Implementation Strategy

### Core Principles

1. **Zero Downtime**: Keep old fields during migration for rollback safety
2. **Incremental Deployment**: Deploy and test each phase separately
3. **Data Integrity**: Always backup before migration
4. **User Communication**: Clear notifications about system changes
5. **Testing First**: Update E2E tests before deploying to production

```typescript
// New helper functions
function generateProviderStudentId(
  firstName: string,
  lastName: string,
  providerId: Id<"providers">
): string {
  const timestamp = Date.now().toString(36);
  const nameHash = `${firstName.substring(0, 2)}${lastName.substring(0, 2)}`.toUpperCase();
  const providerHash = providerId.substring(0, 4).toUpperCase();
  const random = Math.random().toString(36).substring(2, 6).toUpperCase();
  return `${providerHash}-${nameHash}-${timestamp}-${random}`;
}

function generateAutoGuardianId(firstName: string, lastName: string): string {
  const timestamp = Date.now().toString(36);
  const nameHash = `${firstName.substring(0, 2)}${lastName.substring(0, 2)}`.toUpperCase();
  const random = Math.random().toString(36).substring(2, 6).toUpperCase();
  return `GUA-${nameHash}-${timestamp}-${random}`;
}
```

**Update create mutation**:

```typescript
export const create = mutation({
  args: {
    firstName: v.string(),
    lastName: v.string(),
    schoolId: v.optional(v.id("schools")),
    providerId: v.optional(v.id("providers")), // NEW - replaces guardianId
    grade: v.optional(v.string()),
    class: v.optional(v.string()),
    // ... other fields
  },
  handler: async (ctx, args) => {
    // Validate XOR: must have schoolId OR providerId, not both
    if (args.schoolId && args.providerId) {
      throw new Error("Cannot link to both school and provider");
    }
    if (!args.schoolId && !args.providerId) {
      // Auto-guardian mode (no provider specified)
      // This is OK - will generate auto-guardian ID
    }

    // Generate student ID based on context
    const studentId = args.providerId
      ? generateProviderStudentId(args.firstName, args.lastName, args.providerId)
      : args.schoolId
      ? generateStudentId(args.firstName, args.lastName, args.schoolId)
      : generateAutoGuardianId(args.firstName, args.lastName);

    // Create student
    const newStudentId = await ctx.db.insert("students", {
      studentId,
      firstName: args.firstName,
      lastName: args.lastName,
      schoolId: args.schoolId,
      providerId: args.providerId, // NEW
      // Don't set guardianId anymore
      // ... rest of fields
    });

    return newStudentId;
  },
});
```

```typescript
export const createOrGetAutoGuardian = mutation({
  args: {
    teacherId: v.id("users"),
  },
  handler: async (ctx, args) => {
    const teacher = await ctx.db.get(args.teacherId);
    if (!teacher) throw new Error("Teacher not found");

    // Check if auto-guardian provider exists for this teacher
    const existing = await ctx.db
      .query("providers")
      .filter(q =>
        q.and(
          q.eq(q.field("category"), "guardian"),
          q.eq(q.field("createdBy"), args.teacherId),
          q.eq(q.field("isAutoGenerated"), true)
        )
      )
      .first();

    if (existing) return existing._id;

    // Create auto-guardian provider
    const providerId = await ctx.db.insert("providers", {
      name: `Auto-Guardian - ${teacher.username}`,
      nameTh: `ผู้ปกครองอัตโนมัติ - ${teacher.username}`,
      category: "guardian",
      createdBy: args.teacherId,
      isActive: true,
      isAutoGenerated: true,
      createdAt: Date.now(),
    });

    return providerId;
  },
});
```

## 🚨 Risk Mitigation

### High-Risk Areas

1. **Data Migration Failure**:
   - **Mitigation**: Dry-run mode, backup before migration
   - **Detection**: Migration log, verification queries
   - **Response**: Rollback mutation, restore from backup

2. **User Workflow Disruption**:
   - **Mitigation**: Keep old fields during migration
   - **Detection**: User feedback, error reports
   - **Response**: Quick rollback, gradual migration

3. **E2E Test Failures**:
   - **Mitigation**: Update tests before deploying
   - **Detection**: CI/CD pipeline
   - **Response**: Fix tests or rollback changes

### Medium-Risk Areas

1. **Performance Degradation**:
   - **Mitigation**: Use indexed queries, batch fetching
   - **Detection**: Convex dashboard metrics
   - **Response**: Optimize queries, add indexes

2. **UI Confusion**:
   - **Mitigation**: Clear provider vs school labeling
   - **Detection**: User feedback
   - **Response**: Improve UI labels and help text
