# MongoDB Atlas - API Key Authentication Guide

**Date:** October 31, 2025  
**Use Case:** Alternative to database user password for backups

---

## 📋 Overview

MongoDB Atlas provides **two types of authentication**:

1. **Database User (Username/Password)** - For data access ✅ **Recommended for backups**
2. **Atlas Admin API Key** - For cluster management ⚠️ **Not for direct data access**

---

## ✅ Recommended: Reset Database User Password

### Step-by-Step Instructions

1. **Log in to MongoDB Atlas**
   - Go to <https://cloud.mongodb.com>
   - Sign in with your account

2. **Navigate to Database Access**
   - In the left sidebar, click **"Database Access"**
   - You'll see your user **"EvilEvan"**

3. **Reset Password**
   - Click **"Edit"** button next to "EvilEvan"
   - Click **"Edit Password"**
   - Choose one of:
     - **"Autogenerate Secure Password"** (recommended)
     - **"Password"** and enter your own
   - **IMPORTANT:** Copy the password immediately!
   - Click **"Update User"**

4. **Update `.env.local`**

   ```env
   MONGODB_BACKUP_URI=mongodb+srv://EvilEvan:YOUR_NEW_PASSWORD@evansclasstracker.xwif0el.mongodb.net/?appName=EvansClassTracker
   ```

5. **Test Connection**

   ```powershell
   npm run backup
   ```

---

## 🔧 Alternative: Create New Database User

If you can't reset the password, create a new user:

1. **In Database Access, click "Add New Database User"**

2. **Configure User:**
   - Authentication Method: **Password**
   - Username: `backup-user`
   - Password: Click **"Autogenerate Secure Password"** (copy it!)
   - Database User Privileges: **"Read and write to any database"**
   - Built-in Role: Select **"Atlas admin"** or **"Read and write to any database"**

3. **Click "Add User"**

4. **Update `.env.local`:**

   ```env
   MONGODB_BACKUP_URI=mongodb+srv://backup-user:YOUR_PASSWORD@evansclasstracker.xwif0el.mongodb.net/?appName=EvansClassTracker
   ```

---

## ⚠️ Why Not Atlas Admin API Keys?

**Atlas Admin API Keys** are for cluster management (create/delete clusters, users, etc.), NOT for data access.

To access data (which is what the backup script needs), you MUST use:

- Database username/password (recommended)
- Or X.509 certificates (complex setup)

---

## 🔐 Security Best Practices

### Password Storage

- ✅ Store password in `.env.local` (already gitignored)
- ✅ Use autogenerated secure passwords
- ✅ Never commit `.env.local` to Git
- ✅ Rotate passwords every 90 days

### Password Recovery

If you lose your password again:

1. Reset it in MongoDB Atlas (Database Access)
2. Update `.env.local`
3. Test with `npm run backup`

### Password Manager

Consider using a password manager:

- **1Password** - <https://1password.com>
- **Bitwarden** - <https://bitwarden.com> (free & open source)
- **LastPass** - <https://lastpass.com>

## 🆘 Troubleshooting

### "Authentication failed"

- ✅ Check password has no special characters that need URL encoding
- ✅ If password contains `@`, `#`, `:`, etc., URL-encode them:
  - `@` → `%40`
  - `#` → `%23`
  - `:` → `%3A`

### Example with Special Characters

If password is: `P@ss#123`

Encode it as: `P%40ss%23123`

```env
MONGODB_BACKUP_URI=mongodb+srv://EvilEvan:P%40ss%23123@evansclasstracker.xwif0el.mongodb.net/?appName=EvansClassTracker
```

### "User not found"

- ✅ Verify username is correct (case-sensitive)
- ✅ Check user exists in Database Access section
- ✅ Ensure user has permissions for the database
