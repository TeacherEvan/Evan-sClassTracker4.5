# Complete Guardian to Provider Migration Guide

**Date**: December 6, 2025  
**Script**: `scripts/run-guardian-migration.ps1`  
**Backend**: `convex/migrations/completeGuardianMigration.ts`  
**Status**: Ready for execution

## Overview

This migration script performs a comprehensive conversion from the deprecated guardian system to the provider system, including:

1. **Guardian User Migration**: Converts all guardian users to provider entities
2. **Pseudo-Provider Creation**: Auto-creates `{Teacher'sPVTclass}` for self-reference students
3. **Student Migration**: Updates all student relationships to use providerId
4. **Class Migration**: Updates all class relationships to use providerId
5. **Data Integrity**: Preserves legacy fields for rollback safety

## What Gets Migrated

### Phase 1: Guardian Users → Provider Entities

**Before:**

- Guardian users with role = "guardian"
- Students with `guardianId` field
- Classes with `isGuardianLinked` = true

**After:**

- Provider entities with category = "guardian"
- Students with `providerId` set to new guardian provider
- Classes with `providerId` set to new guardian provider
- Legacy fields (`guardianId`, `isGuardianLinked`) preserved for rollback

### Phase 2: Self-Reference Students → Pseudo-Providers

**What are self-reference students?**

- Students created by teachers WITHOUT schoolId or providerId
- Personal students that don't belong to a school or existing provider
- Need organizational structure for queries and filtering

**Solution:**

- Create one `{Teacher'sPVTclass}` pseudo-provider per teacher
- Link all self-reference students to their teacher's pseudo-provider
- Link all related classes to the pseudo-provider

**Before:**

```javascript
Student: {
  firstName: "John",
  lastName: "Doe",
  schoolId: undefined,
  providerId: undefined,
  guardianId: undefined,
  createdBy: teacher_id_123
}
```

**After:**

```javascript
Provider: {
  name: "{Teacher'sPVTclass}",
  nameTh: "{คลาสส่วนตัวของครู}",
  category: "personal",
  createdBy: teacher_id_123,
  isAutoGenerated: true
}

Student: {
  firstName: "John",
  lastName: "Doe",
  schoolId: undefined,
  providerId: pseudo_provider_id,
  guardianId: undefined,
  createdBy: teacher_id_123
}
```

## Rollback Procedure

If migration fails or produces unexpected results, you can rollback:

### Option 1: PowerShell Script (TODO - not yet implemented)

```powershell
.\scripts\rollback-guardian-migration.ps1 -AdminId "j12345678"
```

### Option 2: Manual Convex Command

```powershell
# Dry-run rollback (preview)
npx convex run migrations/completeGuardianMigration:rollbackMigration '{
  "adminId":"j12345678",
  "dryRun":true,
  "confirm":true
}'

# Execute rollback (live)
npx convex run migrations/completeGuardianMigration:rollbackMigration '{
  "adminId":"j12345678",
  "dryRun":false,
  "confirm":true
}'
```

**What rollback does:**

1. Deletes all guardian providers created by migration
2. Deletes all pseudo-providers (`{Teacher'sPVTclass}`)
3. Clears `providerId` from students that have `guardianId`
4. Clears `providerId` from classes that have `isGuardianLinked`

**Rollback limitations:**

- Only works if legacy fields (`guardianId`, `isGuardianLinked`) still exist
- Cannot rollback if legacy fields have been removed from schema
- Manual data restore from backup may be needed for complex scenarios

### Option 3: Database Restore

If rollback fails or data is corrupted:

```powershell
# List available backups
npm run backup:list

# Restore from backup
npm run backup:restore
# Select the pre-migration backup from the list
```

### 3. Monitor for Issues

**Check for:**

- Error reports in `errorReports` table
- User complaints about missing students
- Class booking failures
- Query performance issues

### 4. Optional: Clean Up Legacy Fields

**After 30 days of stable operation**, consider removing deprecated fields:

1. **Update schema** (`convex/schema.ts`):
   - Remove `guardianId` from students table
   - Remove `isGuardianLinked` from classes table
   - Remove `by_guardian_id` index from students
   - Remove "guardian" from user roles

2. **Update code**:
   - Remove guardian-specific logic from `convex/students.ts`
   - Remove guardian-specific logic from `convex/classes.ts`
   - Remove guardian role checks from UI components

3. **Deploy changes**:

   ```powershell
   npx convex deploy
   npm run build
   vercel --prod
   ```

⚠️ **WARNING**: Once legacy fields are removed, rollback becomes impossible!

## Troubleshooting

### Issue: "Admin user not found"

**Solution:**

```powershell
# List all users to find admin
npx convex run users:list

# Look for users with role: "admin"
# Use the correct username or ID
```

### Issue: "Convex CLI not found"

**Solution:**

```powershell
# Install Convex CLI
npm install -g convex

# Or use npx (no installation needed)
npx convex --version
```

### Issue: Migration shows errors

**Solution:**

1. Review error messages in migration report
2. Common causes:
   - Missing students or teachers (deleted data)
   - Corrupted relationships (orphaned records)
   - Permission issues (teacher access to providers)
3. Fix data issues manually or exclude problematic records
4. Re-run migration

### Issue: Verification shows incomplete migration

**Solution:**

1. Check which counts are non-zero
2. Re-run migration (it's idempotent - safe to run multiple times)
3. If persistent, investigate specific records:

   ```powershell
   # Find students without provider
   npx convex run students:list
   # Filter results manually for missing providerId
   ```

### Issue: Students disappear after migration

**Likely cause:** Students are now under provider category, not school

**Solution:**

1. Update UI components to show provider students
2. Check `components/hierarchical-student-selector.tsx`
3. Ensure "Provider Students" section is visible
4. Filter by provider name in student list

## Technical Details

### Migration Functions

| Function | Type | Purpose |
| --- | --- | --- |
| `previewMigration` | Query | Preview what will be migrated (safe) |
| `migrateToProvider` | Mutation | Execute migration (with dry-run option) |
| `verifyMigration` | Query | Check migration success (safe) |
| `rollbackMigration` | Mutation | Undo migration (emergency only) |

### Provider Categories

| Category | Description | Created By |
| --- | --- | --- |
| `guardian` | Migrated guardian users | Migration script (Phase 1) |
| `personal` | Self-reference students pseudo-provider | Migration script (Phase 2) |
| `private` | Private tutoring companies | Teachers/Admins |
| `language_school` | Language schools | Teachers/Admins |
| `educational_camp` | Summer camps, workshops | Teachers/Admins |

### Pseudo-Provider Specifications

- **Name**: `{Teacher'sPVTclass}` (English)
- **Name (Thai)**: `{คลาสส่วนตัวของครู}`
- **Category**: `personal`
- **isAutoGenerated**: `true`
- **Created for**: Each teacher with self-reference students
- **Purpose**: Organizational structure for teacher's personal students

### Data Integrity

**Preserved fields (for rollback):**

- `students.guardianId` - Original guardian user ID
- `classes.isGuardianLinked` - Original guardian flag

**New fields:**

- `students.providerId` - Provider entity ID
- `classes.providerId` - Provider entity ID
- `providers.isAutoGenerated` - Marks pseudo-providers

## Performance Considerations

### Migration Speed

**Estimated time:**

- Small dataset (<100 students): 1-2 minutes
- Medium dataset (100-1000 students): 5-10 minutes
- Large dataset (>1000 students): 15-30 minutes

**Factors:**

- Number of guardian users
- Number of self-reference students
- Number of classes to update
- Database response time

### Database Impact

- **Writes**: Creates new provider records, updates existing students/classes
- **Reads**: Multiple queries to find related records
- **Indexes**: Uses existing indexes (`by_role`, `by_guardian_id`, `by_student`)
- **Transactions**: Not atomic (Convex limitation), but idempotent (safe to retry)
