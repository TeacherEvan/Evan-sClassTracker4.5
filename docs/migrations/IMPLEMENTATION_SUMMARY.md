## Migration Details

### Phase 1: Guardian User Migration

**What it does**:

1. Finds all users with role = "guardian"
2. Creates provider entity for each (category: "guardian")
3. Updates students with `guardianId` to use `providerId`
4. Updates classes with `isGuardianLinked` to use `providerId`
5. Preserves legacy fields for rollback safety

**Example**:

```javascript
Before: User { role: "guardian", username: "parent1" }
        Student { guardianId: user_id_123 }
        Class { isGuardianLinked: true }

After:  Provider { name: "Guardian - parent1", category: "guardian" }
        Student { guardianId: user_id_123, providerId: provider_id_456 }
        Class { isGuardianLinked: true, providerId: provider_id_456 }
```

### Phase 2: Self-Reference Student Migration

**What are self-reference students?**

- Students with NO schoolId, NO providerId, NO guardianId
- Created by teachers for personal tutoring
- Need organizational structure for queries

**What it does**:

1. Identifies students with no school/provider/guardian link
2. Groups by teacher (createdBy field)
3. Creates one `{Teacher'sPVTclass}` pseudo-provider per teacher
4. Links all self-reference students to their teacher's pseudo-provider
5. Updates related classes

**Example**:

```javascript
Before: Student {
          firstName: "John",
          schoolId: undefined,
          providerId: undefined,
          guardianId: undefined,
          createdBy: teacher_id_123
        }

After:  Provider {
          name: "{Teacher'sPVTclass}",
          nameTh: "{คลาสส่วนตัวของครู}",
          category: "personal",
          createdBy: teacher_id_123,
          isAutoGenerated: true
        }
        Student {
          firstName: "John",
          providerId: pseudo_provider_id,
          createdBy: teacher_id_123
        }
```

## Technical Specifications

**Provider Categories**:

- `guardian` - Migrated from guardian users (Phase 1)
- `personal` - Self-reference students (Phase 2)
- `private` - Private tutoring companies
- `language_school` - Language schools
- `educational_camp` - Educational camps

**Pseudo-Provider Naming**:

- English: `{Teacher'sPVTclass}`
- Thai: `{คลาสส่วนตัวของครู}`
- Category: `personal`
- Flag: `isAutoGenerated: true`

**Legacy Fields (preserved)**:

- `students.guardianId` - For rollback
- `classes.isGuardianLinked` - For rollback

**New Fields (added)**:

- `students.providerId` - Provider link
- `classes.providerId` - Provider link
- `providers.isAutoGenerated` - Pseudo-provider flag

## Rollback Information

If migration fails, rollback procedure:

```powershell
# Dry-run rollback
npx convex run migrations/completeGuardianMigration:rollbackMigration '{
  "adminId": "your_admin_id",
  "dryRun": true,
  "confirm": true
}'

# Execute rollback
npx convex run migrations/completeGuardianMigration:rollbackMigration '{
  "adminId": "your_admin_id",
  "dryRun": false,
  "confirm": true
}'
```

**What rollback does**:

- Deletes all guardian providers
- Deletes all pseudo-providers
- Clears providerId from students (keeps guardianId)
- Clears providerId from classes (keeps isGuardianLinked)

**Limitations**:

- Only works if legacy fields still exist
- Cannot rollback if schema has been updated
- May require database restore for complex scenarios
